## 3. Behavior per breakpoint (code-based; screenshots NOT AVAILABLE)

### 375px (phone) — **INFERRED from CSS**

- Dock visible (`display: flex !important`); `content-shell` padding `12px 14px 110px` to clear dock.
- Dash tiles **1 column** (≤640).
- Ask / Priorities / Week / Evening: `align-items: flex-end`, panel `height: 100%`, `border-radius: 0` → full-bleed sheets.
- Notify: absolute under header, 320px wide (may clip on narrow).

- At exactly 768: still in `max-width: 768` → dock on, compressed padding.
- At 769+: dock **hidden**; no alternate Ask chrome on desktop except tiles / Ctrl+K / opening panel.
- Tiles: if width >640, **3-column** grid inside ~600px dashboard column → cramped tile text.

### 1280px (desktop) — **INFERRED**

- Large empty side margins: shell centers to 1100px; dashboard content only 600px wide inside that.

**Design-ref desktop** centers a single ~680 card on darker page chrome — app instead stretches the app-shell full viewport with sticky top-nav and empty flanks.

## 4. Bug list (with evidence)

### Critical / High

1. **All Items ignores `subject_or_title`**  
   - **Evidence:** `AllItemsPage.tsx:87` renders `{r.id}`; type has `subject_or_title?` (`types.ts:9`); API documents AI-05 lite (`generated.ts`).  
   - **Impact:** Users see opaque IDs (`WI-013`) instead of subjects.  
   - **Fix:** `r.subject_or_title ?? r.id`; same for Priorities `ptitle2` (`PrioritiesPanel.tsx:66`). Add vitest.

2. **Static `dayShapeLine` as live briefing prose**  
   - **Evidence:** `DashboardPage.tsx:55` hardcoded string. Session-02 flags this.  
   - **Impact:** False operational claims.  
   - **Fix:** Hide until API exists, or label “Sample week shape” / gate behind demo flag. Prefer hide for honesty.

3. **WeekPanel entirely static fiction**  
   - **Evidence:** `WeekPanel.tsx:15–21` `WEEK` constant; no fetch.  
   - **Impact:** Same.  
   - **Fix:** Demo badge or disable entry until B4 calendar; do not invent live data.

4. **Gear mislabeled / misrouted vs Settings**  
   - **Evidence:** `App.tsx:93` `NavLink to="/connections" aria-label="Settings"`; real Settings at `/settings` via `dash-settings-link` (`DashboardPage.tsx:156–158`). Design README: gear → connections.  
   - **Impact:** a11y + wayfinding confusion.  
   - **Fix:** `aria-label="Connections"`; optional separate settings icon; keep mobile visuals identical except label.

5. **Panel lifecycle inconsistency (regression magnet)**  
   - **Evidence:** Ask/Priorities/Week early-return or conditional; Evening/Voice/Notify class-toggle (`EveningPanel.tsx:53`, `NotifyPanel.tsx:15`, `VoiceOverlay.tsx:15`).  
   - **Impact:** Cascade bugs (documented 90vh override).  
   - **Fix:** One primitive: `PortalOverlay` with single open strategy + shared CSS; migrate one panel at a time behind visual tests.

### Medium

6. **`--fg` / `--fg-muted` undefined** — slide titles / gear may render wrong (`index.css:1523+`). Map to `--text-1` / `--text-3`.

7. **No safe-area / dvh on shell** — dock `padding: 14px 14px 18px` (`index.css:325`); notched devices. Add `env(safe-area-inset-bottom)` to dock and panel input rows only (mobile).

8. **NotifyPanel UX** — no Escape, no click-outside, no scroll lock, z-index 200 under panels. Add Escape + outside click; optional focus trap.

9. **Dashboard triage error silent** — `DashboardPage.tsx:34` `console.error` only → empty urgent state looks “clear”. Surface inline error like Insights.

10. **VoiceOverlay** — no Escape; no scroll lock; mic hidden if unsupported (`MobileDock.tsx:44–53`) with no explanation.

11. **Ask/Evening/Priorities no focus trap** — Tab can escape to dock/page under overlay.

12. **Multiple overlays possible** — Ask + Notify + Voice theoretically; Evening + Ask if both opened from different paths (Notify stays open under Ask).

13. **Evening fetch on every open** — remount OK; closing mid-request relies on cancel flag (**VERIFIED**). Good. But closing copy always shows “Nothing else needs you tonight” even on error path after empty (**EveningPanel.tsx:101–104**) — tone mismatch on error.

15. **Contrast** — `--text-4 #6a6760` on `#141413` and muted italics likely fail WCAG for small text (**INFERRED**; axe in B1.5 to measure). Coral-on-dark banners similar.

16. **Focus visibility** — dashboard tiles have `focus-visible`; many buttons (close ✕, dock, bell, send) rely on browser default / none. Inputs use `outline: none` with border-only focus.

17. **Touch targets** — `page-back` 40×40 OK; `nav-gear` padding 6px may be <44px; notify items OK.

18. **Keyboard** — Ctrl/Cmd+K Ask (**VERIFIED**); no documented shortcuts for panels; Enter sends Ask/dock.

19. **Onboarding localStorage** — try/catch swallow (**useUserName**); if write fails, may re-show onboarding every load (**INFERRED** edge).

20. **Connections `onClick` on `div.cn-cat`** — not keyboard-activatable button (**a11y Medium**).

## 5. Fragility analysis

**High-risk patterns for desktop work:**

1. **Single 2.3k-line `index.css`** with duplicated media blocks and screen sections appended over time.  
2. **Cascade overrides by breakpoint** (the 90vh incident) — any new `@media (max-width: 768px)` can silently fight base panel rules.  
3. **Mixed lifecycle** → different mount timing vs CSS transitions.  
4. **Magic numbers:** 1100 / 720 / 560 / 520 / 600 / 110px dock clearance.  
5. **One `!important`:** `.mobile-dock { display: flex !important }` (`index.css:313`) — fights base `display: none`; desktop dock experiments will fight this.  
6. **Hard-coded colors** parallel to tokens → theme/desktop tweaks miss half the UI.  
7. **Dashboard nested max-widths** inside content-shell — desktop layout must not fight both.

**Containment for B1.5:**

- Introduce layout via **new wrapper classes** (e.g. `.app-shell--desktop`, `.desk-pane`) gated by `min-width: 1024px` only; leave ≤768 rules untouched.  
- Optional CSS split **with zero visual change:**  
  1. Extract sections to `tokens.css`, `shell.css`, `dashboard.css`, `panels.css`, `pages.css` imported from `index.css` in same order.  
  2. Prove with Playwright screenshot diff at 375/768/1280 **before** any selector edits (threshold 0 on mobile).  
  3. No selector renames in the split commit.
